First v2 production release

The development team have achieved feature complete on all response types. There are a few minor features missing some of which have been added to this release. The team delayed the release to fit in a couple of extra features. The majority of development focus is on bug fixing.

New Features

Tap in Cell (choice questions in tables)

In a choice question in a table, where each option is in its own cell, it is now possible to click on the cell (rather than just the control) to change the state of the control.

Grid: question separator

Grids now support separators between the grid and the previous/next questions

Property: Separator

The Property Separator is now honoured at a question level. This is both when a stand alone question and when in a grid. The page property Separator is already supported.

Choice: Read-only Options

Options in a choice question now recognise that they are read-only. There state (selected, not selected) is shown but the value cannot be changed.

Show Questions

A questionname.show() is now honoured. It makes all the questions on the page readonly. This cannot be used in conjunction with a tabstrip as it makes the tabstrip readonly as well.

List: Option visibility

List questions (list, combobox and dropdown) now support option visibility and option invisibility rules.

List: current item highlight

When performing a rollover (desktop) or using the keyboard to move over options in a list, the current item is highlighted to differentiate it from the selected option.

Page Layout of specific questions

This requires a fix from Unicom. The use of custom page layouts is now supported even when a tabstrip (global question) is used. This feature was failing due to a Unicom bug. There is a fix for the bug which should be implemented on the desktop and the servers. This fix is going through testing (it has passed my tests) and will be rolled out the same way as all other fixes. Once implemented a layout template can name specific questions (by name) to determine where on the page they should be positioned.

Bug Fixes

Scale: Special codes not dismissed

When a special code was selected on a scale question, selecting a value on the scale did not dismiss the special code.

Choice: keyboard completion

When using the keyboard to set a value in the other specify the associated radio button/checkbox was not being selected or deselected

Choice: Other specify formatting

The format for an other specify was a box which was causing inconsistent option heights. This is now an underline.

Combobox: MinCharacters causes input to collapse

When MinCharacters was set on a combobox the combobox input would collapse when the user started typing

Combobox: No keyboard actions on filter

When a filter was entered into a combobox to reduce the list of options the keyboard did not seem to navigate through options correctly. This is because it was navigating through filtered (invisible) options. This no longer happens.

Scale: Incorrect pre/post labelling

pre/post labels were incorrectly formatted in scale questions (they had boxes around them).

Answered: Color changed to ensure Accessibility compliance

The Ipsos Green (Teal) colour was used to show answered text/options. It failed accessibility tests and so a slightly darker variation has been applied.
