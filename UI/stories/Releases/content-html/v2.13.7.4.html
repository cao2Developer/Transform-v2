Mobile and Exclusivity Issues

This release looks to resolve several issues. There is a third pending issue that may have been resolved by inference.

Issues Resolved

Exclusive options in a grid dismiss the whole grid

When a grid contains one or more choice questions where the choice includes an exclusive option then the exclusive option was dismissing all selected options. in the grid rather than just the selected options within its question bounds.

Combo: List position on mobile devices

When a combobox is displayed on a mobile phone the list is incorrectly positioned. Further, scrolling will cause the position to change. This is particularly noticeable on an iPhone. The issue is caused when the keyboard appears and the browser automatically (not our code) repositions the current control by scrolling. The combination of a reduction in the available space (caused by the keyboard) and the reposition of the control means that the list is shown in the wrong place.

Exclusive options in a grid are shown incorrectly

In a grid of choice questions where the question is multi-answer but there are exclusive options. The exclusive options were incorrectly displayed. They look like radio buttons but act like checkboxes.

Special codes don't dismiss existing values

A patch to the release was added to resolve an introduced issue where special codes were not dismissing values in their associated question.

Numeric questions in a grid have become exclusive. Entering a value in to one question causes all other questions in the grid to lose their value.

Possible resolution

Comboboxes appear as different sizes in a grid

The team were not able to recreate the issue where a grid of comboboxes could result in different width controls. This may be because we had already implemented the fix for combo on mobile devices and that had fixed the issue. We had already seen that off screen comboboxes were not being sized in the same way as onscreen and had resolved that issue.
