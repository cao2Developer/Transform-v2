Visibility Fixes

This is a patch release providing small improvements to the existing platform. The next full release will occur when all the base Complex Question functionality arrives.

The patch includes server files, an updated question.xsl and updated assets for the example survey. There are no changes apart from the server files; the example survey is just for reference.

New Features

Some new features were added as we resolved issues

Readonly for buttons

Buttons now recognised when the question or the option is readonly and change their styling as appropriate

Reset to Load

The functionality required to allow resets to change back to the original value (when the page loaded) have been completed

Issues Resolved

The following issues have been resolved in this patch.

Dropdown / Dropup

When a dropdown box hits the bottom of the screen and is unable to show all its list, it drops up rather than down.

Buttons don't drive visibility rules

If a question uses buttons and a second question uses the first questions response to define question/option visibility then the visibility state of the second question does not change when the first one is answered. This affected both visibility - options and visibility - question. This has now been resolved for containsAny and answerCount functions within visibility rules.

### Reset to null not working on lists

There were issues with a few response types, but most notably lists. They looked like they had removed their value but the hidden input control had not reset properly causing issues when the page is submitted. In the case of lists some questions could still see a selected value.

Lists show a scroll bar

When a list has all of its options visible there is sometimes a scrollbar visible which causes the list scroll slightly. The lists now fit better so that this does not happen.

Known Issues

There are still some issues that are to be resolved. These are logged as bugs but are currently not given a high priority as we want to focus on complex question functionality.

Comboboxes don't always dropup

When minnumberofcharacters property is set the dropup functionailty does not work as expected because when the list is first revealed it only has one line

Droplist size is not always accurate

The width of the list is sometimes incorrect (slightly too wide or too narrow)

Choice other specify not aligned correctly

When a choice question has balance applied, the other specify option can be vertically misaligned

Combo box exact matches make selecting options difficult

there is an issue with a combo box when exact match is set to true. If there are other options which start the same as the exact match they cannot be selected because the list disappears when the exact match is set. In this case, it is best to turn off exact match.

Boolean labels dont cause selection change

Clicking on a boolean label does not cause the selection of the checkbox to change. The respondent has to click on the checkbox itself.
