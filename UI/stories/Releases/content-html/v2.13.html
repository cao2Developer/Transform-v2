Question Templates

This release is focused on delivering fixes to issues and some missing features vs the v1.96 release. There are some background features around the new complex questions, however these are not yet ready for implementation.

In relation to the upcoming complex questions release we have been focusing on the deployment of pages and blocks. As a result, we have made some changes to the question templates including the introduction of some new ones. There is a bug in Dimensions that we have filed with them. It seems that Pages do not support the application of the question template (to the specific page). They do support the allocation of the question template to the study (iom.questiontemplate = "") but not to the question (question.questiontemplate = ""). Consequently we need to ensure that all individual questions, blocks and grids have a question template assigned to the specific question (rather than use the default template). This will ensure that the defaulttemplate is only used for Pages. A new question page.htm question template is included. This is now the default template.

We know that this means extra work. We have been applying the question template in the metadata, rather than the routing:

METADATA Code
    grid6_subheading "Grid with row subheadings and column total"
    [
       CurrentTab = "IterationTotal"
    ]
    templates(question="question.htm")
    loop { }
    Fields () expand;

There is a change to the list of functions at the bottom of the mdd. This change is to force the page template to be the default template. It looks at each question, if its a page question it then looks for a question template, if there is one it sets the default template to that template. This ensures that the page template is honoured for pages.

Changed SetupQuestion function

ROUTING Code
function SetupQuestion(theQuestion, theParentFullName, theHidden, theIOM)
dim currentName, currentFullname, currentType, currentOrder
dim registerBanner
dim numberOfSubQuestions, counter, subQuestion, subName
dim InstructionBanner, warningBanner
dim iterationCount, iterationCounter, currentIteration
dim questionName, iterationName
dim currentAdjustedName, currentTableName, currentAdjustedTableName
dim currentLoopName, currentAdjustedLoopName

 dim currentAdjustedParentName, currentParentFullname, loopCounter, subLoop, loopQuestionCount
dim iterationIndex
dim currentQuestionType, currentQuestionName

 currentName = theQuestion.QuestionName
 currentAdjustedName = MakeString("_Q", currentName.Replace("_", "__"))
 currentFullname = theParentFullName + currentAdjustedName
 currenttype = theQuestion.QuestionType

'debug.Log(MakeString("name: ", currentName, ", fullname: ", currentFullname, ", type: ", currentType))
 select case(thequestion.QuestionType)
 case QuestionTypes.qtBlock, QuestionTypes.qtPage
  if theQuestion.QuestionType = QuestionTypes.qtPage then
   CheckDefaultTemplate(theIOM, theQuestion, "page")
  else
   CheckDefaultTemplate(theIOM, theQuestion, "block")
  end if
    numberOfSubQuestions = theQuestion.count
  for counter = 0 to numberOfSubQuestions - 1
   set subQuestion = theQuestion[counter]
   SetupQuestion(subQuestion, currentFullName, false, theIOM)
  Next

 case QuestionTypes.qtLoopCategorical
  currentQuestionType = ApplyDefaultQuestionType(theQuestion,false)
  currentQuestionName = ApplyQuestionName(theQuestion, currentFullName)

  currentTableName = theQuestion.QuestionName
  currentAdjustedTableName = MakeString("_Q", currentTableName.Replace("_", "__"))
  iterationCount = theQuestion.Categories.Count

  for counter = 0 to iterationCount - 1
   set subLoop = theQuestion[counter]
   loopQuestionCount = subLoop.count
   currentLoopName = theQuestion.Categories[counter].name
   currentAdjustedLoopName = MakeString("_Q", currentLoopName.Replace("_", "__"))
   currentParentFullname = theParentFullName + currentAdjustedTableName + currentAdjustedLoopName
   for loopCounter = 0 to loopQuestionCount - 1
    set subQuestion = subloop[loopCounter]
    SetupQuestion(subQuestion, currentParentFullName, (currentQuestionType.Find("hidden")>0), theIOM)
   Next
  Next
 case QuestionTypes.qtLoopNumeric
  currentQuestionType = ApplyDefaultQuestionType(theQuestion, false)
  currentQuestionName = ApplyQuestionName(theQuestion, currentFullName)

  currentTableName = theQuestion.QuestionName
  currentAdjustedTableName = MakeString("_Q", currentTableName.Replace("_", "__"))

  iterationCount = theQuestion.Count
  for each subLoop in theQuestion
   loopQuestionCount = subLoop.count
   currentLoopName = subLoop.QuestionName
   currentAdjustedLoopName = MakeString("_Q", currentLoopName.Replace("_", "__"))
   currentParentFullname = theParentFullName + currentAdjustedTableName + currentAdjustedLoopName
   for loopCounter = 0 to loopQuestionCount - 1
    set subQuestion = subloop[loopCounter]
    SetupQuestion(subQuestion, currentParentFullName, (currentQuestionType.Find("hidden")>0), theIOM)
   Next
  next

 case else
  if theQuestion.style.control.type = controltypes.ctEdit then theQuestion.style.control.type = controltypes.ctSingleLineEdit
  LookUpZIndex(theQuestion)
  ApplyDefaultQuestionType(theQuestion, theHidden)
  ApplyQuestionName(theQuestion, currentFullName)
 end select

dim qCurrentTab, qPageProperties, quote
 quote = chrW(34)

 set qPageProperties = theIOM.Questions["PageProperties"]
 ChangePageProperties(theIOM, qPageProperties, MakeString("tab=", quote, qcurrentTab.response, quote), true)

end function

New CheckDefaultTemplate function

ROUTING Code
function CheckDefaultTemplate(theIOM, theQuestion, theType)
dim defaults
 set defaults = theIOM.Questions["defaulttemplates"]
 If theQuestion.QuestionTemplate.Len() < 1 then
  select case theType
  case "page"
   theIOM.QuestionTemplate = defaults.Categories["defaultpage"].label.text
  case "block"
   theQuestion.QuestionTemplate = defaults.Categories["defaultblock"].label.text
  end select
 else
  if theType = "page" then
   theIOM.QuestionTemplate = theQuestion.QuestionTemplate
  end if
 end if

end function

New Features

Multiline

Multiline support has now been added. This requires the use of the response type: multiline and the control type multilineedit.

Metadata

This is an example of the metadata for a multiline response

METADATA Code
    Address "Please provide your full address"
        style(
            BgColor = "multiline:",
            Control(
                Type = "MultiLineEdit"
            )
        )
        templates(
            Question = "question 2-column.htm"
        )
    text [..300]
    codes(
    {
        noaddress "I have no address" REF,
        noanswer "" NA
    } );

Routing

There are no custom properties at this time (there are some in the roadmap). Pre/Post labels are not supported.

Refactored Choice options

There has been a slight change to the way that choice questions are rendered in html. This change is part of the implementation of buttons. The change is only to options that contain an other specify. They will allow button options to sit alongside radiobuttons and checkboxes within a choice question.

Issues resolved

IOM.Title is places the Title in the wrong place.

IOM.Title now places the title above the first question on the page but below the tabstrip (if one is being used). This placement is due to a line in the question template:

HTML Code
<main class='surroundcontent'>
  <h1><mrPageTitle /></h1>

   <mrData>Questions here</mrData>
</main>

If you don't want the title to appear on the page you can remove this from the template. Be aware, however that there is an accessibility requirement on complex pages to have a heading for the page: [WAI Headings](https://www.w3.org/WAI/tutorials/page-structure/headings/).

Grid Totals not recalculating on change of inputs

When a grid question includes totals the totals calculate on page load but not when any input within the table is changed.

Slider does not honour floodtovalue:false

The Flood that appears between the start and the current value of the slider, is displayed regardless of the setting of the custom property. Floodtovalue:false now causes the flood to not be displayed.

Combobox: Minnumberofcharacters causes entry issues

When minnumberofcharacters is greater than 2 there are issues filtering the list of options

Filtering Options: Filtering not working

When a question is setup to filter another list based question (list, combbox, dropdown) then the filtering was not working. This has been partially resolved in the fact that the filter is now working. However, there are still issues.

Options are not filtering

When filter (visibility) rules are applied to closed questions the filtering is not occurring properly (options are not becoming invisible).

Known Issues

The team are pushing this release to provide access to some of the latest improvements. There are more to come, another release will be made before the end of the week.

Options made invisible are not deselected

Selected options that are made invisible are not being de-selected. When they become invisible they should resettonull as they are no longer valid (as they are not considered a valid option). This has been partially resolved (choice questions) but there are still issues for list questions.

Making a Grid invisble does not cascade reset instructions

When a grid is made invisible all of the questions it contains should be resettonull. It is working when individual questions are assigned within the grid, but not when the whole grid is made invisible.

Buttons are partially implemented

Buttons are in progress, but not fully implemented in this release

Formatting issue with Grid Totals

While the issue with Grid totals has been resolved, exceptions within a column can cause a small formatting issue. It is cosmetic and will be resolved in a future release.

Boolean, labels don't change state

Clicking on the label associated with a boolean input (a single checkbox) does not change the boolean's state. the user has to click on the checkbox itself.

Dropdowns do not dropup

When there is insufficient space for a dropdown to show its entire list it should dropup. This is not currently happening.

Readwrite Edit has not yet been implemented

This will be completely refactored. We will not introduce a dedicated question type but apply the functionality to all questions. This will appear in a later release.
