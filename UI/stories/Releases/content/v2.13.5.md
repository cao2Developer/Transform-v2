# Various Fixes

This release has been updated with new fixes.  The additional fixes are marked with an asterisk.  The update changed the server files.

This patch delivers a variety of fixes requested by the team.  This release contains updates to the server side components and an update to question.xsl.  A copy of the latest example survey has also been included.

## New Features

### Combo-box: Exact Match features refined

Exact match is the default setting {exact:true} for combo-boxes.  When a respondent enters text they list is filtered based on their entry.  When an exact match with a list item occurs it is automatically selected.  Now when the user either types more than the exact entry or removes one or more characters so that there is no longer an exact match then the current selection is removed.

### Grid: Iteration labels are formatted differently

A different (slightly smaller font) style has been applied to iteration labels.  Iteration labels are those that appear down the left side of a grid unless the grid is rotated, in which case they appear across the top of the grid.  The style applied is no longer the same as the question label.

## Resolved Issues

### Choice (single-answer): Other Specify Lost

When a respondent makes an entry into the other specify of an option (in a single-answer question) the radio button is not automatically selected.  Furthermore, when it is selected manually the content of the other specify is lost.  This has now been tested for both single answer and multi-answer questions. 

### Grid: Special codes dismiss everything

Special codes across all question types were being too aggressive when presented in a grid.  Rather than just dismiss the answer from the current iteration of the grid they were dismissing the answer from all iterations.  This occurred regardless of the response type used.

### Grid-choice: exclusives dismiss everything

This is the same issue as above in the fact that exclusive options are effectively special codes.  An exclusive option was dismissing all answers within the grid and not just its own answer.

### Combo-box: cannot be used after selection

When a respondent made an entry that was an exact match for an item in the list, they were no longer able to continue typing.  This is problematic when the start of an entry matches two or more options, they could only select the first one by typing.

### Boolean: label does not change state

Boolean questions could only change selected state by direct interaction with the control (checkbox) it is now possible to change the state by clicking on the label associated with that checkbox.

### Pre/post labels don't align correctly in grid based questions when they wrap over multiple lines *

pre/post labels did not have their own alignment assignment, so when they appear in a grid where the cell is centre aligned their alignment was wrong.  Now each pre/post label is conscious of response type and position and aligns appropriately.

### Pre/post labels align to the terminator and not the track when terminators are present. *

Pre/post labels in sliders should align to the ends of the track, they did this when there were no terminators, but when terminators were included they aligned incorrectly. Alignment is now more consistent.

### Grid (choice): its not possible to click in the cell to change state, you have to click on the control *

This functionality was lost for a few releases following a HTML structure change.  It is now possible to click in the cell rather than the control.
