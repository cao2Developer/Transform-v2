<tr>
<th scope="row">Read only state</th>
<td>

Use the native `readonly` attribute, not `disabled`, because a disabled field does not send its value with the form. The field stays in the focus order of the `Tab` key, so users can reach it, review its value and copy it.

Do not add `aria-readonly="true"`, because the native `readonly` attribute already exposes the read only state. The `required` attribute has no effect on a read only field.

</td>
<td>

- [MDN: readonly HTML attribute](https://developer.mozilla.org/en-US/docs/Web/HTML/Reference/Attributes/readonly)
- [MDN: ARIA: aria-readonly attribute](https://developer.mozilla.org/en-US/docs/Web/Accessibility/ARIA/Reference/Attributes/aria-readonly)

</td>
</tr>
<tr>
<th scope="row">Error state</th>
<td>

Set `aria-invalid="true"` on the field only after the form is submitted with a missing or invalid value. Link the field to its error message with `aria-describedby`, so screen readers announce the message together with the field.

The error icon and the message show the error without depending on color alone.

</td>
<td>

- [MDN: ARIA: aria-invalid attribute](https://developer.mozilla.org/en-US/docs/Web/Accessibility/ARIA/Reference/Attributes/aria-invalid)
